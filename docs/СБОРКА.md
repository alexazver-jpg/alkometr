# СБОРКА И ПОДПИСЬ

Пошаговая инструкция для того, кто впервые открывает Android-проект. Все команды — из папки
`alkometr` (корень проекта, где лежит `gradlew.bat`).

## 1. Что понадобится

| Компонент | Версия | Зачем |
|---|---|---|
| Android Studio | любая актуальная | IDE, запуск и отладка |
| JDK | 17 (можно встроенный в Studio) | компиляция Kotlin/Java |
| Android SDK Platform | **37** | `compileSdk = 37` |
| Build-Tools | **37.0.0** | сборка APK |
| Gradle | **9.8.2** | скачивается wrapper-ом автоматически |
| AGP | **9.5.1** | подключается из Google Maven |

Ставить Gradle вручную не нужно: `gradlew.bat` сам скачает версию 9.8.2 в
`C:\Users\<вы>\.gradle\wrapper\dists`.

## 2. Открыть проект в Android Studio

1. **File → Open** и выбрать папку `alkometr` (ту, где `settings.gradle.kts`).
2. Дождаться **Gradle Sync**. Первый sync скачивает зависимости, это несколько минут.
3. Если Studio просит указать SDK: **Tools → SDK Manager** → отметить
   `Android SDK Platform 37`, `Android SDK Build-Tools 37`, `Android SDK Platform-Tools`.
4. Файл `local.properties` Studio создаст сама; он в `.gitignore` и в репозиторий не попадает.

## 3. Сборка debug-версии

В Android Studio: **Build → Build App Bundle(s) / APK(s) → Build APK(s)**.

Или в терминале:

```powershell
gradlew.bat :app:assembleDebug
# готовый файл: app\build\outputs\apk\debug\app-debug.apk
```

Установка на подключённый телефон (включена отладка по USB):

```powershell
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

## 4. Release-подпись

Release-APK нельзя установить без ключа. Ключ проекта «АлкоМетр» лежит **вне репозитория**:

```
C:\Users\<вы>\.alkometr\keys\
├── alkometr-release.jks      ← сам ключ (PKCS12, RSA 2048, срок 10 000 дней)
└── keystore.properties       ← путь к ключу и пароли (только для этого пользователя)
```

`app/build.gradle.kts` читает `keystore.properties` при сборке. Если файла нет,
release-сборка останется неподписанной, а debug собирается как обычно.

Сборка:

```powershell
gradlew.bat :app:assembleRelease
# готовый файл: app\build\outputs\apk\release\app-release.apk
powershell -File tools\check_apk.ps1 -Apk app\build\outputs\apk\release\app-release.apk -Release
```

Проверка подписи вручную:

```powershell
& "C:\Users\user\AppData\Local\Android\Sdk\build-tools\37.0.0\apksigner.bat" verify --print-certs app\build\outputs\apk\release\app-release.apk
```

В выводе должно быть `CN=Alkometr`.

### Важно про ключ

- **Никогда не коммитить** `*.jks`, `*.keystore`, `keystore.properties`: они в `.gitignore`.
- **Сделайте резервную копию** папки `%USERPROFILE%\.alkometr\keys` (например, на флешку или
  в менеджер паролей). Потеря ключа означает, что обновление приложения поверх установленного
  выпустить уже нельзя — придётся менять `applicationId`.
- Пароли хранятся в `keystore.properties` в открытом виде (так устроен Gradle). Это локальный
  файл, доступный только вашему пользователю; в репозиторий он не попадает.
- Если нужно пересоздать ключ (например, для нового приложения):

```powershell
keytool -genkeypair -keystore "$env:USERPROFILE\.alkometr\keys\alkometr-release.jks" `
  -storetype PKCS12 -alias alkometr -keyalg RSA -keysize 2048 -validity 10000 `
  -dname "CN=Alkometr, O=Personal, C=RU"
```

`keytool` спросит пароль интерактивно — так он не попадёт в историю команд. После этого
впишите новые `storePassword`/`keyPassword` в `keystore.properties`.

## 5. Тесты и проверки

```powershell
gradlew.bat :app:testDebugUnitTest    # 31 юнит-тест
gradlew.bat :app:lintDebug            # статический анализ
powershell -File tools\check_apk.ps1  # проверка debug-APK без устройства
```

Либо одним скриптом, который сам находит JDK и SDK и пишет лог в `docs/build-log.txt`:

```powershell
powershell -ExecutionPolicy Bypass -File tools\build.ps1 -Tasks :app:assembleDebug
```

## 6. Частые ошибки

| Сообщение | Причина | Что делать |
|---|---|---|
| `SDK location not found` | нет `local.properties` и переменной `ANDROID_HOME` | открыть проект в Studio или задать `ANDROID_HOME`; скрипт `tools\build.ps1` делает это сам |
| `Starting in Kotlin 2.0, the Compose Compiler Gradle plugin is required` | забыт плагин Compose | он уже подключён в `app/build.gradle.kts` (`libs.plugins.compose.compiler`) |
| `requires ... compile against version 37` | старый `compileSdk` | установить Platform 37 и оставить `compileSdk = 37` |
| `Module was compiled with an incompatible version of Kotlin` | слишком новая библиотека | не поднимать `kotlinx-serialization-json` выше 1.9.0: встроенный Kotlin в AGP — 2.2.10 |
| `Keystore file not set for signing config release` | нет `keystore.properties` | создать ключ по разделу 4 или собирать debug |
| Эмулятор падает / синий экран | конфликт WHPX и VMware на этой машине | проверять на реальном телефоне по `adb` |

## 7. Что где лежит в сборке

```
settings.gradle.kts        список модулей и репозитории зависимостей
build.gradle.kts           плагины для всего проекта
gradle/libs.versions.toml  единый список версий (AGP, Compose, библиотеки)
gradle.properties          настройки Gradle (память, кэш, AndroidX)
app/build.gradle.kts       настройки модуля: SDK, версии, Compose, подпись, зависимости
app/src/main/              код, ресурсы, манифест
app/src/test/              юнит-тесты на JVM
```

Полезно помнить: **версии меняются в `libs.versions.toml`**, а не в случайных местах; `compileSdk`
и `minSdk` — в `app/build.gradle.kts`; тексты — в `res/values/strings.xml`; иконки — в `res/drawable/`.
