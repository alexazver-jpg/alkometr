## 1. Репозиторий GitHub

Приватный репозиторий **не создан**. Причина прежняя: в системе нет `gh` (GitHub CLI) и не задан
`GITHUB_TOKEN`, поэтому публикация из этой сессии невозможна. Исходники лежат в локальном
репозитории `alkometr` и в локальном архиве `E:\ProectsAutoClaw\АлкоМетр`.

Для публикации добавлен скрипт `tools\publish_github.ps1`. Он работает двумя путями: через `gh`,
если CLI установлен и авторизован, либо через GitHub API по `GITHUB_TOKEN`. В обоих случаях скрипт
создаёт **приватный** репозиторий (или продолжает работу, если он уже есть), ставит `origin`
и проверяет приватность: анонимный `GET https://api.github.com/repos/<owner>/alkometr` должен
вернуть `404`. Токен читается только из переменной окружения, не печатается и не пишется в файл.

```powershell
# из папки alkometr
powershell -ExecutionPolicy Bypass -File tools\publish_github.ps1
```

Ручной вариант:

```bash
gh auth login
gh repo create alkometr --private --source=. --remote=origin --push
gh repo view --json name,url,isPrivate
```

Ожидаемый результат: `publish_github.ps1` печатает `OK: anonymous request returned 404`,
а `gh repo view` — `"isPrivate": true` и URL репозитория. До этого шага пункт «Репозиторий»
в приёмке (`docs/ПРИЁМКА.md`) считается заблокированным.

Ссылка на репозиторий в приложении уже заготовлена, но скрыта: строка `settings_repository_url`
в `res/values/strings.xml` пуста, и блок «Репозиторий проекта» в «О приложении» не показывается,
пока в неё не вписан URL. После публикации достаточно вписать адрес и пересобрать APK.

оставлена пустой. Пересчитать при необходимости:

```powershell
Get-FileHash dist\alkometr-0.1.0-debug.apk -Algorithm SHA256
```

## 6. Скриншоты

**Живые кадры новой вёрстки не сняты.** Файлы в `docs/screenshots/` относятся к предыдущей сборке
(10.11.2026) и показывают интерфейс до правок второго раунда: иконка степени 72 dp, шкала времени
внутри прокручиваемого содержимого, список порций — сворачиваемый блок, а не диалог, в профиле
нет роста и возраста.

Причина: эмулятор в этом окружении падает сразу после установки APK. На машине одновременно активны
WHPX (Windows Hypervisor Platform) и драйверы VMware Workstation 15.5.6 — это рабочее объяснение
конфликта гипервизоров, а не доказанный диагноз: логи запусков (`docs/emulator.log`,
`docs/emulator2.log`) фиксируют только старт эмулятора и обрываются. Из-за падения прогон
останавливался, чтобы не терять результаты сборки и тестов.

|---|---|
| `01-onboarding.png` | Онбординг первого запуска: шаг «Ваш вес», далее пол, порог, дисклеймер; можно пропустить |

Проверка экранов выполнялась 10.11.2026 на эмуляторе Pixel_8 с debug-APK предыдущей сборки:
онбординг проходится и не повторяется, пустой экран показывает «Трезв», тап по сосуду добавляет
порцию и поднимает уровень, настройки открываются с главного.

**К сборке 11.11.2026 эта проверка не повторялась** — эмулятор падает (раздел 6). Для текущей
сборки подтверждены сборка, 31 юнит-тест, lint без ошибок и проверки APK; поведение экранов
проверено по коду, но не глазами. Поэтому в `docs/ПРИЁМКА.md` визуальные пункты помечены
как «показ устарел», а не «выполнено».

Инструментальные тесты (`androidTest`) не писались — это ограничение относится и к первому выпуску.

## 8. Отклонения от ТЗ

| Пункт ТЗ | Факт | Причина |
|---|---|---|
| compileSdk 36 | compileSdk **37**, targetSdk 36 | Compose BOM 2026.09.00 (Compose 1.12.1) требует compileSdk 37; `android-37.0` — стабильный релиз, ТЗ разрешает максимальный стабильный compileSdk |
| Compose только через `buildFeatures.compose` | дополнительно плагин `org.jetbrains.kotlin.plugin.compose` 2.2.10 | без него AGP 9.5.1 не собирает Compose: «Starting in Kotlin 2.0, the Compose Compiler Gradle plugin is required» |
| kotlinx-serialization без версии | 1.9.0 | 1.12.0 собрана Kotlin 2.4 и несовместима со встроенным компилятором 2.2.10 (ошибка metadata 2.4.0) |
| Навигация через библиотеку | ручное состояние экранов + `BackHandler` | экранов три, `androidx.navigation` даёт лишнюю зависимость |
| Иконка степени 72 dp в центре шкалы | **42 dp** | в центре дуги в одном столбце стоят число, единица и подпись степени; 42 dp оставляют место числу и работают при крупном системном шрифте |
| Масштаб шкалы времени 0,5×…6× | **30 мин…48 ч**, панорама двумя пальцами + кнопки | абсолютное окно понятнее кратности; 48 ч согласованы с горизонтом прогноза 24 ч, нижняя граница 30 мин даёт разобрать одну порцию |
| «Отменить» для последней порции | только для порции, добавленной в текущей сессии | кнопка отменяет последнее действие в приложении, а не правит историю; старые порции удаляются в «Истории» свайвом |
| Отдельные `SettingsViewModel` / `HistoryViewModel` | всё через `MainViewModel` | один источник состояния «порции + настройки + кривая»; отдельные VM дублировали бы подписки и пересчёт |
| Все строки в `strings.xml` | русские служебные строки также в `Formatters`, `Units`, `BackupCodec` | их проверяют JVM-тесты без контекста Android; сообщения `BackupCodec` показываются как текст ошибки импорта |
| Всплывающее «+0,28 ‰» — фактический прирост | верхняя оценка `D / Vd` | мгновенный прирост зависит от фазы всасывания и выведения и всегда меньше `D / Vd`; показываем верхнюю границу, чтобы не занижать |

Отклонения не меняют расчётную модель: константы, уравнения и контрольные значения те же, что
в `docs/АЛГОРИТМ.md`.

## 9. Что осталось за рамками

* **Публикация на GitHub** — заблокирована: нет `gh` и `GITHUB_TOKEN`. Скрипт и команда — раздел 1;

* **Инструментальные тесты** — `androidTest` не писались, экраны проверены вручную на прежней сборке.
* **CI** — автоматическая сборка на сервере не настраивалась.
* **SHA-256 текущего APK** — не зафиксирован в протоколе; команда пересчёта — раздел 3.
