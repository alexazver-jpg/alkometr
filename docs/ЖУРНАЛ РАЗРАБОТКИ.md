# ЖУРНАЛ РАЗРАБОТКИ — проект «АлкоМетр»

## 2026-11-09. Этап 1. Промпт-задание для ИИ-разработчика

### Задача

Подготовить самодостаточный промпт для ИИ-агента, который разработает Android-приложение на Kotlin: расчётный уровень алкоголя в крови, шкала на главном экране, кнопки «стопка / бокал / кружка», шкала времени с прошлым и будущим уровнем, пять степеней опьянения со смешными иконками, приватный репозиторий GitHub.

### Проверка версий инструментов

Запрошены Gradle 9.8.2 и AGP 9.5.1. Проверено по первоисточникам:

| Компонент | Факт | Источник |
|---|---|---|
| Gradle 9.8.2 | существует, стабильный релиз; актуальный на дату — 9.9.0 | `services.gradle.org/versions/all`, `versions/current` |
| AGP 9.5.1 | существует, стабильный; последний — 9.6.0-alpha03 | Google Maven `com.android.tools.build:gradle/maven-metadata.xml` |

Вывод: версии не выдуманы, требования ТЗ выполнимы, подменять их не нужно.

### Находка по AGP 9.x

Начиная с AGP 9.0 **удалена поддержка применения Kotlin Gradle Plugin** (`org.jetbrains.kotlin.android`): Kotlin встроен в AGP, компилятор поставляется вместе с плагином. Это критично для промпта — иначе исполнитель напишет конфигурацию в стиле AGP 8 и получит непонятную ошибку на старте. В промпт добавлены раздел 1.1 и запрет в разделе 15.

Дополнительно в промпт введён обязательный «этап 0» — сборка пустого Compose-проекта на этих версиях до написания логики (проверка совместимости за 10 минут вместо дня отладки).

### Медицинская часть: константы модели

| Величина | Значение | Обоснование |
|---|---|---|
| Объём распределения | r = 0,71 л/кг (муж) / 0,58 (жен) | формула Видмарка |
| Скорость выведения | 0,15 г/л/ч (диапазон 0,10–0,20) | Widmark, обзоры фармакокинетики этанола |
| Всасывание | первый порядок, ka = 2,0 / 1,5 / 0,8 ч⁻¹ | натощак / обычно / плотно поел |
| Плотность этанола | 0,789 г/мл | физическая константа |

Модель: всасывание первого порядка + выведение по Михаэлису–Ментену (`Vmax = 0,15`, `Km = 0,02`). Нулевой порядок на высоких концентрациях воспроизводится автоматически, «хвост» не уходит в минус.

### Калибровка модели

Первая версия считалась с `Km = 0,05`: 80 кг, одна стопка 50 мл 40 % — полное выведение за 4,2 ч. Нереалистично: при такой дозе человек трезвеет примерно за час, а не за четыре.
Снижение `Km` до 0,02 дало 2,98 ч для той же дозы и сохранило плавный хвост. Значение зафиксировано в промпте.

### Контрольные значения (получены эталонным скриптом `_check_model.py`)

### Решения по структуре промпта

1. Порядок разделов повторяет порядок работы исполнителя: роль → версии → данные → математика → уровни → экраны → архитектура → тесты → git → приёмка.
2. Добавлен явный список того, **какие данные нужны от пользователя** (ответ на вопрос из ТЗ): обязательны только вес и пол, остальное — уточнения.
3. Юридический порог отделён от пяти степеней опьянения, иначе приложение начнёт врать: при пороге 0,5 ‰ степень «лёгкое опьянение» формально допускает вождение, но реакция уже снижена.
4. Прописаны критерии приёмки в виде чек-листа с доказательствами (лог сборки, число тестов, `isPrivate`, анонимный запрос к API даёт 404).
5. Внесено правило владельца: `ReadMe.md` в проекте и архиве, локальный git-архив `E:\ProectsAutoClaw\АлкоМетр\`, коммит после каждого этапа.

## 2026-11-10. Этапы 0–7. Приложение собрано

### Окружение

Готового Android-окружения на машине не было: JDK, SDK и Gradle взяты из локального набора
`E:\ProectsAutoClaw\_tools` (Temurin 17.0.20.1, android-sdk, wrapper). Доустановлены
`platforms;android-36`, `platforms;android-37.0`, `build-tools;36.0.0/37.0.0`.

### Этап 0. Spike

Первая сборка упала трижды, каждая ошибка была ожидаемой и полезной:

| Ошибка | Причина | Решение |
|---|---|---|
| `Starting in Kotlin 2.0, the Compose Compiler Gradle plugin is required` | AGP 9 не включает компилятор Compose сам | подключён `org.jetbrains.kotlin.plugin.compose` 2.2.10 — версия встроенного в AGP Kotlin |
| `SDK location not found` | в `local.properties` путь был записан с экранированием `E\:` | путь через прямые слэши |
| 11 issues AAR metadata: Compose 1.12.1 требует compileSdk 37 | актуальный Compose BOM собран под SDK 37 | установлен `platforms;android-37.0`, compileSdk = 37, targetSdk = 36 |

Результат: `BUILD SUCCESSFUL` на Gradle 9.8.2 + AGP 9.5.1 + Compose. Логи — `docs/build-log*.txt`.

### Этапы 1–2. Модели и движок

`core/engine` написана без `android.*`: всасывание первого порядка, выведение Михаэлиса–Ментена,
Эйлер с шагом 1 минута. Внутри — старт не раньше `now − 24 ч`, поэтому старые порции не влияют.

Первые 19 тестов: 15 зелёных сразу, 4 упали, и все четыре — по делу:

1. `deleteDrink_recomputesHistory` сравнивал значение на 20-й минуте, а удалялась порция на 30-й — тест был неверен, сравниваем на 40-й.
2. `addDrink_raisesLevelImmediately` ждал роста в ту же миллисекунду; физически порция начинает всасываться со следующей минуты — проверяем через минуту.
3. `timeFormatter_ru`: 30 секунд давали «1 мин» вместо «меньше минуты» — ошибка форматтера, исправлена.
4. `eliminationSlope…` мерил наклон сразу после пика, когда всасывание ещё идёт; перенесено на 4-й час после большой дозы, где работает нулевой порядок (0,148 ‰/ч).

Все пять контрольных сценариев ТЗ совпали с эталоном `_check_model.py` без подгонки констант.

### Совместимость Kotlin

`kotlinx-serialization-json` 1.12.0 тянет stdlib 2.4.10, а встроенный компилятор AGP — 2.2.10:
`Module was compiled with an incompatible version of Kotlin`. Откат на 1.9.0 решил проблему.
Отдельно поймано: PowerShell пишет BOM в TOML — каталог версий перезаписан без BOM.

### Этапы 3–6. Интерфейс

Собраны дуговая шкала (240°, пять зон, маркер-стрелка, пунктир порога, пульсация опасной зоны),
статусная карточка, кнопки сосудов, шкала времени на Canvas (прошлое/прогноз, порог, маркеры
порций, cursor, щипок и кнопки масштаба), настройки, онбординг, история со свайпом,
пять собственных векторных иконок-персонажей и три иконки сосудов, светлая и тёмная темы.

Замеченные и исправленные огрехи: подписи делений шкалы выходили за границы Canvas (перенесены
внутрь дуги), подписи возраста порций обрезались снизу (высота шкалы 160 → 190 dp), четыре чипа
единиц не помещались в строку (разбиты на две строки), сообщение «+0,28 ‰» собиралось подстановкой
строки — заменено на нормальный `stringResource`.
