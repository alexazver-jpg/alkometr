# РОЛЬ И ЗАДАЧА

Ты — ведущий Android-инженер: Kotlin, Jetpack Compose, Gradle, чистые архитектурные границы, тесты, git. Ты работаешь самостоятельно в терминале, собираешь APK, доводишь проект до состояния «собирается, тесты зелёные, репозиторий приватный». Вопросы задаёшь только там, где без ответа нельзя двигаться; всё остальное решаешь сам и фиксируешь решение в README.

**Задача:** разработать с нуля готовое к установке Android-приложение «АлкоМетр» — офлайн-трекер **расчётной** концентрации алкоголя в крови (BAC).

Приложение не измеряет алкоголь, а моделирует его по выпитому: пользователь нажимает кнопку с изображением стопки / бокала / кружки, программа добавляет порцию и показывает, как уровень растёт (всасывание) и как падает (метаболизм и выведение).

## Обязательный функциональный минимум

1. Главный экран показывает текущий уровень алкоголя в крови **в промилле (‰)** в виде **шкалы-индикатора** (дуговая шкала со стрелкой/маркером и цветовыми зонами).
2. В настройках задаются: **вес пользователя**, **объём** сосуда (бокал / стопка / кружка), **крепость** напитка.
3. На главном экране — **кнопки с изображениями** стопки, бокала и кружки. Нажатие = выпитая порция прямо сейчас.
4. После нажатия уровень **плавно растёт** по скорости всасывания и **снижается** по скорости метаболизма и выведения — в реальном времени, без участия пользователя.
5. В нижней части главного экрана — **шкала времени**: на ней видны выпитые порции, их давность («−1 ч 20 мин»), прошлая, текущая и **прогнозная будущая** кривая уровня.
6. При прокрутке/перетаскивании шкалы времени показывается уровень на выбранный момент (в том числе будущий) и **сколько осталось до возможности сесть за руль**.
7. Пять степеней опьянения, у каждой — **своя смешная иконка** и своё название.
8. Проект выложен в **приватный** репозиторий GitHub.

## 1.1. Особенности AGP 9.x — читать обязательно

Начиная с AGP 9.0 **плагин Kotlin Gradle Plugin (`org.jetbrains.kotlin.android`) больше не применяется**: поддержка Kotlin встроена в AGP, компилятор Kotlin поставляется вместе с плагином (в AGP 9.0.0 это Kotlin 2.2.10).

Правила:

- **Не подключай** `org.jetbrains.kotlin.android` и не задавай версию Kotlin вручную в `libs.versions.toml`.
- `plugins { id("com.android.application") version "9.5.1" apply false }` — этого достаточно.
- Настройки компилятора Kotlin задавай тем DSL, который предоставляет AGP 9.5.1 для встроенного Kotlin (сверься с официальной документацией «Built-in Kotlin» на developer.android.com). Если DSL отличается от привычного `kotlinOptions` — используй актуальный и опиши его в README.
- Compose включай через `android { buildFeatures { compose = true } }`. Если AGP 9.5.1 требует отдельного плагина компилятора Compose — применяй официально рекомендованный способ для AGP 9 и зафиксируй версию в отчёте.
- **Версии Gradle 9.8.2 и AGP 9.5.1 не менять.** Обе версии существуют и являются стабильными (проверено: Gradle 9.8.2 есть в списке релизов, AGP 9.5.1 опубликован в Google Maven).

# 2. ДАННЫЕ О ПОЛЬЗОВАТЕЛЕ

## 2.1. Ответ на вопрос «какие ещё данные нужны»

Для расчёта **обязательны только два параметра**: **вес** и **пол** (пол определяет объём распределения). Всё остальное — уточнения, без них приложение работает на разумных значениях по умолчанию.

| Параметр | Обязателен | На что влияет | Диапазон | По умолчанию |
|---|---|---|---|---|
| Вес | **да** | объём распределения Vd, скорость выведения | 30–200 кг | спрашивать при первом запуске |
| Пол | **да** | коэффициент r: 0,71 (М) / 0,58 (Ж) | М / Ж / не указан | «не указан» → r = 0,65 |
| Рост | нет | резерв для уточнения Vd (в бэклог) | 120–220 см | — |
| Возраст | нет | резерв для уточнения Vd (в бэклог) | 18–100 лет | — |
| Приём пищи | нет | скорость всасывания ka | натощак / обычно / плотно поел | обычно |
| «Опыт» (толерантность) | нет | скорость выведения Vmax | редко / умеренно / часто | умеренно |
| Порог для вождения | нет | линия на шкалах, расчёт «за руль через…» | 0–0,8 ‰ | 0,3 ‰ |
| Единицы | нет | отображение | ‰ / % / мг/100 мл / мг/л | ‰ |

**Чего НЕ нужно:** ФИО, e-mail, аккаунт, геолокация, доступ к контактам, камере, микрофону. Приложение обязано работать без единого разрешения.

## 2.2. Экран первого запуска (онбординг)

Три шага, пропускаемые:

1. «Ваш вес» — слайдер + числовое поле, кнопка «Дальше» неактивна, пока не введено корректное значение.
2. «Пол» — три варианта (М / Ж / не указывать) с пояснением, зачем это нужно.
3. «Порог для вождения» — пресеты: Россия 0,3 ‰ · Европа 0,5 ‰ · США 0,8 ‰ · Нулевая толерантность 0,0 ‰ · Свой.
4. Дисклеймер (см. п. 11) с кнопкой «Понятно, начать».

Повторно онбординг не показывать (флаг в DataStore). Все параметры доступны в настройках.

# 3. МАТЕМАТИЧЕСКАЯ МОДЕЛЬ

Модель обязана быть **чистой функцией** от (список порций, параметры пользователя, время) — без накопления состояния «в памяти». Тогда любое действие (добавили порцию, удалили, изменили вес) пересчитывает всю кривую заново и прошлое/настоящее/будущее всегда согласованы.

## 3.1. Величины и константы

| Величина | Обозначение | Значение | Комментарий |
|---|---|---|---|
| Плотность этанола | ρ | 0,789 г/мл | перевод объёма в массу |
| Масса чистого спирта в порции | D | V × (ABV/100) × ρ | V — объём в мл, ABV — крепость в % об. |
| Коэффициент распределения | r | 0,71 (муж) / 0,58 (жен) / 0,65 (не указан) | формула Видмарка |
| Объём распределения | Vd | r × вес, л | 80 кг, муж → 56,8 л |
| Скорость всасывания | ka | 2,0 (натощак) / 1,5 (обычно) / 0,8 (плотно поел) ч⁻¹ | первый порядок |
| Максимальная скорость выведения | Vmax | 0,15 г/л/ч (медленно 0,12 · быстро 0,18) | нулевой порядок при высоких концентрациях |
| Константа Михаэлиса | Km | 0,02 г/л | «хвост» выведения, чтобы кривая не уходила в минус |
| Шаг интегрирования | Δt | 1 минута | детерминированно и достаточно точно |
| Горизонт прогноза | — | 24 ч от первой порции | дальше всё равно ноль |

Источники констант: модель Видмарка и обзоры фармакокинетики этанола (Vd = 0,71/0,58 л/кг; скорость выведения в среднем 0,15 г/л/ч, диапазон 0,10–0,20; всасывание описывается кинетикой первого порядка). Значения **не подгоняй** под обучающую выборку — это физиологически обоснованные средние.

## 3.2. Уравнения

```text
Для каждой порции i:
    D_i = V_i × (ABV_i / 100) × 0,789              [граммы этанола]
    a_i(t) — масса ещё не всосавшегося алкоголя, г
    da_i/dt = −ka × a_i ,   a_i(t_i) = D_i          [всасывание, 1-й порядок]

Суммарная скорость поступления в кровь:
    input(t) = ka × Σ a_i(t)                        [г/ч]

Баланс концентрации:
    dC/dt = input(t) / Vd − Vmax × C / (Km + C) ,   C ≥ 0
    C(0) = 0

Выведение:
    при C >> Km  →  Vmax×C/(Km+C) ≈ Vmax  (нулевой порядок ≈ 0,15 ‰/ч)
    при C → 0    →  скорость падает, кривая асимптотически подходит к нулю
```

Интегрирование: явный метод Эйлера с шагом 1 минута, `C = max(0, C + dC)`, массы `a_i` уменьшаются на `ka·a_i·Δt` с отсечением по нулю. Этого достаточно: при шаге 1 мин ошибка относительно RK4 — менее 1%.

## 3.3. Производные величины

- **Текущий уровень** — значение кривой на `now`, интерполяция между минутами.
- **Пик** — максимум кривой: значение и время.
- **Время до порога** `T_drive` — первый момент после текущего, когда `C(t) ≤ threshold` (кривая после пика монотонно убывает, поэтому решение единственное). Если `C(now) ≤ threshold` — вернуть «можно сейчас».
- **Время до нуля** — аналогично для `C(t) ≤ 0,001 ‰`.
- **Остаток** — `T_drive − now` в формате «2 ч 14 мин».

## 3.4. Крайние случаи (обязательно обработать)

| Ситуация | Поведение |
|---|---|
| Нет ни одной порции | кривая = 0, шкала в нуле, статус «Трезв» |
| Добавили порцию | кривая пересчитывается целиком; в точке `now` появляется излом вверх |
| Удалили/отредактировали порцию | полный пересчёт, прошлые точки меняются — это ожидаемо |
| Изменили вес/пол/ka/Vmax | полный пересчёт всей кривой |
| Прошло больше 24 ч | C = 0, события старше 24 ч не влияют на расчёт, но остаются в истории |
| Часы переведены / смена часового пояса | всё хранится в epoch-миллисекундах UTC, отображение — локальное время |
| Уровень > 4 ‰ | шкала упирается в максимум, показывается предупреждение «опасная зона», число всё равно точное |
| Приложение закрыто и открыто | состояние восстанавливается из сохранённых порций и параметров |

## 3.5. Контрольные значения для тестов

Получены эталонной реализацией этой модели (шаг 1 мин). Допуск при проверке: **±0,02 ‰ и ±10 мин**. Если расхождение больше — ищи ошибку в единицах измерения или интеграторе, а не подгоняй тест.

| Сценарий | Ожидание |
|---|---|
| **A.** Мужчина 80 кг, 1 стопка 50 мл 40 % (15,8 г) в t=0 | C(30 мин) = 0,097 ‰; C(60 мин) = 0,102 ‰; пик 0,106 ‰ на 47-й мин; ноль через 2,98 ч |
| **B.** Женщина 70 кг, 1 кружка 500 мл 5 % (19,7 г) | C(60 мин) = 0,252 ‰; C(120 мин) = 0,195 ‰; пик 0,252 ‰ на 65-й мин; ноль через 4,18 ч |
| **C.** Мужчина 90 кг, 3 стопки 50 мл 40 % в 0, 15, 30 мин | C(60 мин) = 0,374 ‰; пик 0,434 ‰ на 97-й мин; до 0,3 ‰ — 3,17 ч; ноль через 5,97 ч |
| **D.** Женщина 60 кг, 2 бокала 150 мл 12 % в 0 и 20 мин | C(60 мин) = 0,454 ‰; пик 0,506 ‰ на 95-й мин; ноль через 6,43 ч |
| **E.** Мужчина 80 кг, 500 мл 5 % в 0 + 50 мл 40 % на 10-й мин, ka = 2,0 | C(60 мин) = 0,399 ‰; пик 0,402 ‰ на 68-й мин |

Дополнительные инварианты:

- наклон кривой на участке 1,5–2,5 ‰ ≈ **0,15 ‰/ч** (допуск ±0,02);
- кривая никогда не отрицательна и не возрастает после пика;
- два одинаковых вызова движка дают побитово одинаковый результат (детерминизм);
- C(t) не зависит от того, в каком порядке добавлены порции.

# 4. ПЯТЬ СТЕПЕНЕЙ ОПЬЯНЕНИЯ

Уровень определяется по текущему значению C, границы — константы в коде, вынесены в один объект.

| № | Диапазон, ‰ | Название | Подпись на экране | Цвет зоны |
|---|---|---|---|---|
| 1 | 0,00–0,20 | **Трезв** | «Можно за руль» | #2E7D32 зелёный |
| 2 | 0,20–0,50 | **Лёгкое опьянение** | «Расслаблен, реакция чуть хуже» | #9CCC65 салатовый |
| 3 | 0,50–1,50 | **Среднее опьянение** | «Весёлый, за руль нельзя» | #FBC02D жёлтый |
| 4 | 1,50–2,50 | **Сильное опьянение** | «Ты почти не стоишь. Такси» | #EF6C00 оранжевый |
| 5 | 2,50+ | **Опасное отравление** | «Риск для жизни. Звони 112» | #C62828 красный |

**Важно:** юридический порог (`threshold`) и степень опьянения — разные вещи. Статус «можно за руль» считается **по порогу** (по умолчанию 0,3 ‰), а не по номеру уровня. Если у пользователя порог 0,5 ‰, то при 0,4 ‰ он формально в норме права, но приложение всё равно пишет «реакция снижена» — так и должно быть.

# 6. ЭКРАНЫ

## 6.1. Главный экран

Сверху вниз:

1. **Верхняя панель:** название, иконка настроек, меню (обнулить сессию, история, о программе).
2. **Дуговая шкала** (высота ~260 dp, занимает ширину экрана):
   - дуга 240°, разбита на 5 цветных сегментов по границам уровней, шкала 0…4 ‰ с подписями 0, 1, 2, 3, 4;
   - маркер-стрелка на текущем значении, плавная анимация 400 мс при изменении;
   - в центре: крупное число `0,42` (48 sp) + знак `‰` (24 sp); под ним название степени с иконкой 72 dp;
   - пунктирная линия юридического порога с подписью «порог 0,3 ‰»;
   - выше 2,5 ‰ зона мягко пульсирует красным.
3. **Статусная карточка:**
   - «Можно за руль» (зелёная) — если `C ≤ порога`;
   - «За руль через 2 ч 14 мин · около 23:40» (красная) — иначе;
   - мелким шрифтом: «Пик 0,43 ‰ был в 21:05» или «Пик ещё впереди: 0,51 ‰ около 22:40».
4. **Кнопки напитков** — ряд из 3–4 крупных кнопок (высота 88 dp, иконка сосуда + название + объём/крепость):
   - «Стопка 50 мл · 40 %», «Бокал 150 мл · 12 %», «Кружка 500 мл · 5 %», «+ Свой»;
   - тап — добавить порцию **сейчас** (тактильный отклик, всплывающее «+0,28 ‰», короткая анимация);
   - долгое нажатие — редактировать объём/крепость этого пресета;
   - «+ Свой» — диалог: объём, крепость, время (по умолчанию сейчас).
5. **Строка последней порции:** «5 мин назад · Стопка 50 мл · 40 %» + кнопка «Отменить».
6. **Шкала времени** (см. п. 6.2) — прижата к низу, высота 190 dp.

Поведение: значение обновляется раз в секунду; после сворачивания/разворачивания пересчитывается по фактическому времени; экран не блокируется, всё работает офлайн.

## 6.2. Шкала времени (ключевой элемент)

Горизонтальная прокручиваемая диаграмма «уровень от времени», нарисованная на Canvas.

**Ось X — время.** Окно по умолчанию: от `min(первая порция − 30 мин, now − 6 ч)` до `now + max(6 ч, T_drive + 2 ч)`. Масштаб 0,5×…6× (щипок двумя пальцами + кнопки «+»/«−»), прокрутка пальцем, автопозиционирование на «сейчас» при открытии.

**Ось Y — промилле,** от 0 до `max(пик × 1,15; порог × 1,6; 0,5)`.

**Что обязательно видно:**

1. Кривая: прошлое — сплошная линия с заливкой-градиентом, будущее — пунктир, цвет зависит от уровня.
2. Вертикальная линия «сейчас» с меткой.
3. Горизонтальная пунктирная линия порога и точка её пересечения с кривой, подписанная временем «23:40».
4. **Маркеры выпитых порций** под осью: иконка сосуда (стопка/бокал/кружка), цвет по крепости, подпись давности «−1 ч 20 мин» для прошлых и «+15 мин» для будущих (если порция добавлена задним числом/на будущее).
5. Сетка по часам с подписями времени (21:00, 22:00…), адаптивно: при сильном уменьшении — раз в 2–3 часа.

**Перетаскивание (scrub):** палец по графику двигает вертикальный курсор; над ним карточка:
`22:40 · 0,42 ‰ · Весёлый · до порога 1 ч 05 мин`.
Внизу закреплена строка: «За руль: с 23:40 · через 2 ч 14 мин». Если выбранное время в прошлом — показывается фактическое (расчётное) значение; если в будущем — прогноз.

**Доступность:** все элементы с `contentDescription`; альтернативный текстовый список порций ниже графика (сворачиваемый) для TalkBack.

## 6.3. Настройки

Разделы:

- **Профиль:** вес (слайдер 30–200 + поле), пол, рост, возраст.
- **Напитки:** список пресетов с редактированием и удалением, «Добавить пресет» (название, объём, крепость, иконка сосуда).
- **Модель:** «Приём пищи» (натощак / обычно / плотно поел) → ka; «Метаболизм» (медленный / средний / быстрый) → Vmax. Под спойлером «Дополнительно» — ручные значения ka, Vmax, Km, r с кнопкой «Вернуть рекомендуемые» и предупреждением, что ручные значения ломают типовой расчёт.
- **Порог и единицы:** пресеты страны, свой порог, единицы отображения (‰ / % / мг/100 мл / мг/л).
- **Данные:** экспорт в JSON, импорт, «Очистить историю», «Сбросить всё».
- **О приложении:** версия, дисклеймер, ссылка на репозиторий.

Любое изменение настроек немедленно пересчитывает кривую и главный экран.

## 6.4. История (дополнительный экран)

Список порций за последние 7 дней: дата, время, напиток, объём, граммы спирта. Свайп — удалить. Кнопка «Добавить за прошлое время» (диалог с выбором даты и времени).

## 7.1. API движка (обязательная форма)

```kotlin
data class Drink(
    val id: String,
    val atMillis: Long,
    val volumeMl: Double,
    val abvPercent: Double,

    val vmaxGPerLH: Double,     // 0.15

data class CurvePoint(val atMillis: Long, val bacGPerL: Double)

object BacEngine {

    fun bacAt(drinks: List<Drink>, p: ModelParams, atMillis: Long): Double
    fun peak(drinks: List<Drink>, p: ModelParams, fromMillis: Long, toMillis: Long): PeakInfo
    fun timeToThreshold(drinks: List<Drink>, p: ModelParams, fromMillis: Long, threshold: Double): Long?  // epoch millis или null
}
```

# 13. ОГРАНИЧЕНИЯ И ЮРИДИЧЕСКАЯ ЧАСТЬ

Приложение **оценочное**. Оно не измеряет алкоголь, а считает модель: реальные значения отличаются на ±20–30 % и зависят от здоровья печени, генетики, лекарств, еды, усталости.

Текст дисклеймера (обязателен на первом запуске и в настройках, дословно):

> «АлкоМетр» рассчитывает уровень алкоголя по формуле Видмарка и средней скорости метаболизма. Это приблизительная оценка, а не медицинское измерение. Индивидуальные отклонения достигают 30 %. Приложение не заменяет алкотестер и не является доказательством в спорах. Никогда не садитесь за руль после алкоголя, даже если приложение показывает допустимое значение. При признаках тяжёлого опьянения (потеря сознания, рвота, холодная кожа) — зовите скорую (112).

Дополнительно:

- не показывать рекламу алкоголя и не подталкивать к употреблению («выпей ещё» — запрещено, «добавить порцию» — можно);
